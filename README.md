# Lalu Kumar Portfolio

Production portfolio for an applied AI and full-stack engineer. The site combines static case studies with a server-proxied AI assistant and an evidence investigation workbench.

## What is included

- Next.js App Router pages for the homepage, background, projects, and metadata routes.
- Curated case studies with architecture disclosures, decision records, evidence notes, and source links.
- Streaming assistant UI with execution stages, source display, cache state, and recoverable failures.
- Document investigation workbench with selected evidence, citation checks, comparison, replay, and JSON export.
- Offline browsing through bundled corpus data and recorded runs when the backend is unavailable.

## Stack

Next.js 16, React 19, TypeScript, Tailwind CSS 4, Zustand, React Markdown, and native browser APIs. No additional runtime dependency is required for local content or offline workbench replay.

## Run locally

Requirements: Node.js 18 or newer and npm.

```sh
npm install
cp .env.example .env.local
npm run dev
```

The development server runs at `http://localhost:3000`. Set these server-only variables in `.env.local` to enable live assistant and workbench requests:

```env
BACKEND_API_BASE=http://localhost:8080
BACKEND_API_SECRET_KEY=<same value as backend API_SECRET_KEY>
```

Never expose these values with a `NEXT_PUBLIC_` prefix. Without them, static pages and recorded workbench replay remain available; live AI calls show an unavailable state.

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Positioning, selected work, capabilities, experience, and contact |
| `/about` | Background, education, and professional profile |
| `/projects` | Project index |
| `/projects/[slug]` | Static case study with architecture and decisions |
| `/lab` | Portfolio assistant and workbench entry point |
| `/lab/documents` | Evidence selection, live runs, comparison, replay, and export |

Unknown project slugs return the application 404 page. `/sitemap.xml`, `/robots.txt`, and `/opengraph-image` are generated by the App Router.

## Content and assistant knowledge

Public project content lives in `src/data/portfolio.ts`; owner-provided résumé data lives in `src/data/resume.json`. The backend sync command merges these sources by project slug, with case studies taking precedence. Keep project links and evidence qualifications in the case study when changing claims.

```sh
cd ../Lalu-Portfolio_Backend
npm run knowledge:refresh
```

Return to this directory and run the production build afterward. The frontend `prebuild` hook checks that the committed backend snapshot matches current case-study content.

## Validation

```sh
npm run typecheck
npm run lint
npm run test:chat
npm run test:lab
npm run build
npm run start
```

For browser checks, use the existing script in `tests/browser/portfolio.cjs` with Playwright and a running production server. The test covers navigation, keyboard interaction, live-stream states, replay, metadata routes, responsive overflow, and accessibility. Backend validation is documented in `../docs/portfolio-validation.md`.

## Deployment notes

Build with `npm run build`, then serve with `npm run start`. Configure the two backend proxy variables in the hosting environment. Keep the backend API secret server-only and deploy frontend and backend revisions together when project knowledge changes.
